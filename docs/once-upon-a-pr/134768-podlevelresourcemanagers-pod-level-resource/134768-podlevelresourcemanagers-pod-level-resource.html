What Could Break

The review risk is mostly cross-manager consistency.

  • risk feature gates must move togetherPodLevelResourceManagers assumes PodLevelResources is enabled wherever pod.spec.resources appears.
  • risk CPU and Memory guards must matchDivergent empty-pool handling would admit pods one manager cannot allocate.
  • risk checkpoint fallback hides corrupt V3 readsA bad V3 read can fall back to V2, losing pod assignments until rebuild.
  • risk tests are mostly node-shape dependentInsufficient NUMA or CPU topology can skip the exact cases reviewers care about.
