# Must-consider and deprioritize heuristics

Two-sided filter used in Phase 2 by the `diff-analyzer`:

- **Must-consider** patterns (top half of this file) flag files that critical-path code shouldn't be silently dropped. The architect downstream may still merge them into a grouped bullet, list them on the Skipped slide, or skip them entirely if the change is mechanical — but the architect must *consider* them, not let them slip through unseen.
- **Deprioritize / boilerplate** patterns (bottom half) flag files that should not get their own code slide even if they happen to live under a must-consider path. They land on the Skipped slide unless they also have non-trivial behavior.

A file can match both. When it does, the analyzer sets both flags and lets the architect decide. The default outcome for "must-consider AND boilerplate" is the Skipped slide with a one-bullet rationale.

---

# Must-consider patterns

Patterns that automatically mark a file as `must_consider: true` in Phase 2. These are the safety net — the LLM may find other interesting things, but these should never be missed.

## Security & auth

- Files under `**/auth/**`, `**/authn/**`, `**/authz/**`, `**/permissions/**`, `**/rbac/**`.
- Diffs containing: `hasPermission`, `isAdmin`, `requireAuth`, `bypassAuth`, `@PreAuthorize`, `policy`, `guard`.
- Changes to JWT/session/cookie config.
- **Reason:** `security-sensitive path`.

## Data layer

- DB migrations: `**/migrations/**`, `**/schema.prisma`, `**/*.sql`, Flyway/Liquibase paths.
- ORM model/entity changes (adding/removing fields, changing types).
- **Reason:** `schema change`.

## External integrations

- New imports from SDKs for payment, identity, CRM, messaging: `stripe`, `salesforce`, `mulesoft`, `twilio`, `sendgrid`, `segment`, `intercom`.
- New HTTP clients pointing at non-internal domains.
- Changes to webhook handlers (`**/webhooks/**`, `**/callbacks/**`).
- **Reason:** `new external integration` or `integration change`.

## Public API surface

- Route/controller files: `**/routes/**`, `**/controllers/**`, `**/handlers/**`, `**/api/**`.
- OpenAPI/GraphQL schema files: `*.openapi.yaml`, `schema.graphql`, `*.proto`.
- Added/removed endpoints.
- **Reason:** `public API change`.

## Infrastructure & deploy

- Terraform, CloudFormation, Kubernetes manifests, Dockerfiles, CI workflows.
- Environment variable additions to `.env.example`.
- **Reason:** `infra/deploy change`.

## Dependencies

- `package.json`, `pnpm-lock.yaml`, `requirements.txt`, `Gemfile`, `go.mod`, `Cargo.toml`, `pom.xml` with new top-level dependencies (not just version bumps).
- **Reason:** `new dependency`.

## Feature flags

- Any addition under `**/flags/**`, `**/features/**`, or matching `featureFlag`, `launchDarkly`, `split.io`.
- **Reason:** `feature flag`.

## UI entry points

- New routes in frontend routers: `**/router.ts`, `**/routes.tsx`, `pages/**`, `app/**/page.tsx`.
- **Reason:** `new UI route`.

## Heuristic interaction rules

- A file can match multiple heuristics — concatenate reasons.
- If a file matches a heuristic AND has `lines_added < 5`, still mark must-consider but flag `suggested_window_expansion: true` so the curator widens the window to include surrounding context.
- A test file (`*.test.*`, `*.spec.*`, `__tests__/**`) matching a heuristic is downgraded to `interesting_score: 0.5` unless the test file itself is the only mention (e.g., new test for a new auth rule).

## What NOT to must-consider

- Pure formatting/whitespace changes.
- Lockfile-only changes (the `package.json` bump is the signal, not the lockfile).
- Generated files (detect by common patterns: `**/generated/**`, `*.gen.ts`, files with `@generated` header).
- `.gitignore`, editor configs, commit hooks.

# Deprioritize / boilerplate patterns

Patterns that mark a file as `boilerplate: true` and pin its `interesting_score ≤ 0.3`. These files do **not** get their own code slide — they land on the Skipped slide, grouped by category. They may still appear in a grouped bullet on a section/outro slide if they're contextually relevant.

The intent: a deck is only useful if it cuts the noise. A 12-file PR where 8 files are routine plumbing should produce a deck about the 4 real changes, not 12 code slides.

## Routine route handlers mirroring siblings

A new file under `**/routes/**` or `**/controllers/**` whose body is a thin delegate (`return service.method(req.body)` and the like) and whose shape mirrors existing siblings in the same directory.

- **Skipped category:** `routine route handlers`
- **Why:** the reviewer infers the shape from one sibling; reading 5 of them is wasted skim time.
- **Override:** if the handler adds non-trivial validation, auth logic, or a non-standard response shape, drop the boilerplate flag.

## Autogenerated migrations with no data movement

ORM-generated migration files (Prisma `migrations/*/migration.sql`, TypeORM, Liquibase) where the diff is purely DDL with no `UPDATE`, `INSERT`, or `DELETE`, no triggers, no concurrent-index hints.

- **Skipped category:** `generated migrations`
- **Why:** the schema change itself is summarized on the cover or a section bullet; the migration file is mechanical.
- **Override:** anything with a backfill, a `NOT NULL` on an existing column, an index lock concern, or a default-then-drop pattern → drop the boilerplate flag (this is now a `must_consider` migration risk).

## Snapshot / lockfile / generated-file churn

- Test snapshot updates (`__snapshots__/**`, `*.snap`).
- Lockfile changes (`pnpm-lock.yaml`, `package-lock.json`, `yarn.lock`, `Cargo.lock`, `poetry.lock`) without a corresponding manifest change.
- Generated client files (`**/generated/**`, `*.gen.ts`, files with a `@generated` header).
- Compiled output committed by mistake.
- **Skipped category:** `snapshot updates` / `lockfile churn` / `generated files`
- **Why:** these are mechanical artifacts of changes that *are* in the deck.

## Pure renames / mechanical refactors

A file whose entire diff is a rename, an import-path update, a directory move with no body change, or a global identifier rename applied uniformly.

- **Skipped category:** `mechanical renames`
- **Why:** the rename is interesting once at the cover or section level; reading 30 import-path updates is not.
- **Override:** if the rename changes semantics (different export, narrower type, public API rename) → drop the boilerplate flag.

## Mirror test files for new code

A new test file added alongside a new source file, where the test file is the obvious mirror (`foo.ts` + `foo.test.ts`) and the deck already shows the source file.

- **Skipped category:** `mirror tests`
- **Why:** the source-file slide implicitly covers "tests added" — the test file rarely surfaces a new risk.
- **Override:** if the test file *itself* is the interesting thing (e.g., the only place the new auth rule is exercised, or it covers the off-path of a feature flag) → drop the boilerplate flag and elevate `interesting_score`.

## Type-only changes

Files where the diff is purely TypeScript type definitions, GraphQL schema-only adjustments, or DTO type updates with no runtime code change.

- **Skipped category:** `type-only changes`
- **Why:** type changes are usually a downstream consequence of another change in the deck. The reviewer will see them by skimming.
- **Override:** if the type change is the contract (e.g., a public API DTO whose field semantics changed) → drop the boilerplate flag.

## Doc tweaks, README touch-ups, code comments only

Files where the diff is purely documentation, README/CHANGELOG additions, JSDoc comments, or inline `//` comment updates.

- **Skipped category:** `doc tweaks`
- **Why:** docs accompany the change; they don't *are* the change.
- **Override:** if the PR is docs-only (the whole point is the doc rewrite) → drop the boilerplate flag for the headline doc file(s) only.

## Boilerplate interaction rules

- Boilerplate flag does **not** prevent must-consider — files can be both. When both: ship to Skipped with a one-bullet rationale instead of a code slide.
- The Skipped slide groups by `Skipped category` label. Aggregate counts: `12 routine route handlers · 6 generated migrations · 18 snapshot updates`.
- Override conditions are non-exhaustive — when in doubt, the analyzer sets both flags and leaves the call to the architect.
